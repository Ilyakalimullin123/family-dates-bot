# Family Dates Bot

Telegram-бот для семейных дат, общих событий в группах и выбора подарков.

## Возможности

- Карточки дней рождения, годовщин и других событий.
- Отдельные списки для личных чатов и каждой группы.
- Напоминания за 30, 21, 14, 7 и 1 день в 10:00 (по умолчанию Asia/Almaty).
- Ссылки и фотографии подарков, рекомендации на основе правил и обратной связи.
- Удаление событий с подтверждением.
- Очистка диалога создания карточки и команда `/clean` для сообщений интерфейса.
- Приглашения близким самостоятельно передать имя и дату в выбранный список с явным подтверждением.
- Личные вишлисты со ссылкой, скрытым от владельца бронированием и отменой брони.
- Учёт источников первого обращения и ключевых действий; закрытый отчёт `/stats`.
- Выгрузка всех дат текущего чата в `.ics` для iPhone и Google Calendar; опциональная подписка с автообновлением.

## Запуск

Нужны Python 3.11+ и работающий PostgreSQL. Текущая локальная установка проверена на Python 3.14 и PostgreSQL 14.

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Создайте базу `family_dates_db` и задайте настройки в терминале:

```bash
export BOT_TOKEN='YOUR_TELEGRAM_BOT_TOKEN'
export DATABASE_URL='postgresql+asyncpg://postgres:postgres@localhost:5432/family_dates_db'
export DEFAULT_TIMEZONE='Asia/Almaty'
python family_dates_bot.py
```

Замените токен и реквизиты PostgreSQL своими значениями. Не публикуйте реальные секреты. Файл `.env` автоматически не читается: приложение использует переменные окружения.

При старте бот создаёт таблицы и обновляет существующую схему для групп. Старые личные события сохраняются. `schema.sql` — исходная справочная схема; актуальная инициализация находится в `init_db_and_seed` в Python-файле, запускать SQL вручную не требуется.

## Команды

| Команда | Действие |
| --- | --- |
| `/start`, `/menu`, `/events` | Актуальный список событий |
| `/new`, `/add` | Добавить карточку |
| `/clean` | Удалить сообщения интерфейса и свои сообщения в личном чате, показать свежий список |
| `/invite` | Создать приглашение для сбора дат (в группе — для администраторов) |
| `/wishlist` | Личный список желаний, добавление подарков и ссылка для друзей |
| `/calendar` | Все даты чата для iPhone / Google Calendar: файл и, после настройки сервера, подписка |
| `/cancel` | Отменить текущий ввод |
| `/stats` | Агрегированная статистика, только владельцам из `BOT_ADMIN_IDS` в личном чате |
| `/campaign метка` | Ссылка для источника привлечения, только владельцам |
| `/export_dataset` | Экспорт данных рекомендаций для событий текущего чата |

## Группы

Добавьте бота в группу, отправьте `/new` и отвечайте именно на вопросы бота. После создания события включите уведомления в карточке. Все участники группы могут управлять её карточками. Личные события автоматически в группы не переносятся.

В группах для удаления ответов пользователей в диалоге создания карточки дайте боту право удаления сообщений. `/clean` сохраняет напоминания и обычную групповую переписку. В личном чате команда также удаляет входящие сообщения пользователя, зарегистрированные после обновления: команды, текст и медиа, даже если у бота нет обработчика для них. Сохраняются только ID чата и сообщения, без содержимого. Telegram обычно разрешает удаление только в течение 48 часов; более старые и не зарегистрированные ботом сообщения могут остаться.

## Проверки

Тесты без подключения к Telegram и базе:

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

Интеграционная проверка PostgreSQL:

```bash
python tests/check_group_isolation.py
```

Интеграционная проверка создаёт/обновляет схему в настроенной базе и стартовый каталог; тестовые события откатываются. Для неё рекомендуется отдельная тестовая база через `DATABASE_URL`.

## Ограничения текущей версии

- Бот должен постоянно работать: выключенный компьютер не отправляет напоминания. GitHub хранит код, но не запускает бота постоянно.
- Запускайте один экземпляр polling-процесса на токен.
- Незавершённые диалоги хранятся в памяти и теряются при перезапуске.
- С 10:00 до конца дня каждые 15 минут проверяются неотправленные напоминания текущего дня; после перезапуска в это время проверка запускается сразу. Напоминания за прошлые дни не досылаются. Журнал исключает повторную отправку успешно зарегистрированных уведомлений; при сбое между доставкой Telegram и записью в БД повтор возможен.
- Рекомендации используют правила и статистику, отдельная ML-модель не обучается.
- Для размещения на сервере нужны PostgreSQL, переменные окружения, резервные копии базы и менеджер процесса.

## Приглашения, желания и рост

В меню доступны «Пригласить близких добавить даты» и, в личном чате, «Мои желания».
Приглашение действует 30 дней. Автор может отозвать его кнопкой под ссылкой.
Получатель вводит имя и день рождения в личном чате с ботом, видит название целевого
списка и подтверждает передачу. Год необязателен. Событие создаётся только в целевом
чате, с включёнными напоминаниями. Одна подтверждённая дата на человека и целевой чат;
после удаления события организатором дату можно передать заново. Для групп приглашение
должен создать действующий администратор; его полномочия проверяются и при подтверждении.
Обычные права управления карточками целевого чата сохраняются.

Вишлист содержит до 20 желаний: название и необязательную HTTP(S)-ссылку. Любой человек,
получивший ссылку, может посмотреть список в личном чате с ботом и забронировать подарок.
Владелец не видит статус брони и того, кто выбрал подарок. Друзья видят, что подарок занят,
но не личность другого дарителя. Отменить бронь может только её автор. Владелец может
удалить желание или отключить старую ссылку; при смене ссылки брони сохраняются,
поэтому друзьям нужно передать новую ссылку для управления ими. Вишлист самостоятельный,
пока не привязан к конкретному событию; после праздника бронь снимается вручную.

Ссылки содержат случайный токен, а не Telegram ID. Не публикуйте приглашения открыто:
получившие ссылку смогут добавлять даты. Бот не рассылает приглашения автоматически —
пользователь выбирает адресата через кнопку «Поделиться». Владельцам бота и БД технически
доступны сохранённые данные, включая бронирования; скрытие от именинника обеспечено интерфейсом.

Для доступа к `/stats` и `/campaign` задайте `BOT_ADMIN_IDS='123456789,987654321'` в окружении
процесса (нужны реальные Telegram ID владельцев). По умолчанию доступ закрыт.
Пример: `/campaign almaty_family_01`. Отчёт показывает первый источник и уникальных
пользователей по действиям с момента включения аналитики. Первое обращение не перезаписывается
при последующих переходах. Открытие ссылки для отправки не означает фактическую отправку.
Аналитика хранит Telegram ID, название действия, время и источник; тексты пожеланий и даты
рождения в неё не копируются. Отчёт не рассчитывает расходы и удержание.

Новые таблицы `growth_*` создаются автоматически при старте без изменения существующих
карточек. При обновлении сервера включите `growth.py` в архив и заранее сделайте резервную копию.
Сценарий пилота и готовые тексты: [docs/growth-pilot.md](docs/growth-pilot.md).

Проверка новых сценариев PostgreSQL во временной схеме с откатом:

```bash
venv/bin/python tests/check_growth.py
```

## iPhone и Google Calendar

Откройте `/calendar` или кнопку «iPhone / Google Календарь» в меню. Файл `family-dates.ics`
содержит все события именно этого чата, включая события с выключенными уведомлениями Telegram.
В личном чате чужие или групповые даты не добавляются. События ежегодные, на весь день,
без привязки к часовому поясу; 29 февраля повторяется 28 февраля в обычные годы, как в боте.
Экспортируются названия и дни/месяцы. Отдельный год рождения, подарки, ссылки на подарки и
брони не экспортируются. Идентификаторы событий стабильны при изменениях и миграции группы.

**Без домена:** скачать файл и импортировать. На iPhone Apple поддерживает импорт `.ics`
из приложения Mail; в Google Calendar — через веб-версию на компьютере, «Настройки →
Импорт и экспорт». Telegram сам не может молча записать события в календарь телефона.
Файл — разовая копия: изменения и удаления в боте не обновляют импортированные события.
Рекомендуется отдельный календарь «Семейные даты»; повторный импорт зависит от приложения
и может привести к дублям. Уведомления в календаре пользователь настраивает отдельно.

**Автоматическая подписка:** после настройки постоянного HTTPS-адреса появится кнопка
«Создать ссылку подписки». Пользователь один раз подключает ссылку в Apple Calendar или
через «Другие календари → Добавить по URL» в веб-версии Google Calendar на компьютере.
Календари сами запрашивают обновления; мгновенная синхронизация не гарантируется.
Синхронизация односторонняя: изменения делаются в боте, календарь отображает их.

Подписка помечает события как `CLASS:PUBLIC`, чтобы они отображались у подписчика
Google с правом чтения: сочетание `CLASS:PRIVATE` и `TRANSP:TRANSPARENT` скрывает
события от такого подписчика. Это не делает календарь общедоступным в Google и
не отменяет секретный токен ссылки. Разовый файл сохраняет `CLASS:PRIVATE`.
После исправления старой пустой подписки можно подключить тот же URL с `?v=2`,
а прежнюю подписку убрать из списка Google, чтобы не получить дубли.

Ссылка содержит случайный 256-битный токен и предоставляет доступ любому, кто её знает.
В группе создавать и отзывать ссылку могут только администраторы. В личном чате — его
владелец. Ссылка не создаётся без нажатия пользователя. «Отключить ссылку подписки» после
подтверждения закрывает дальнейшее чтение; уже сохранённые календарями копии не удаляются.
Новая ссылка требует повторного подключения календаря. При обычных обновлениях ссылка
не меняется. HTTP-журнал приложения отключён, чтобы не записывать токены в access log.

Без `CALENDAR_PUBLIC_BASE_URL` HTTP-сервер не запускается, работает только скачивание файла.
Для подписки нужен обратный прокси с HTTPS к `127.0.0.1:8088`. Настройка — в
[deploy/README.md](deploy/README.md). Таблица `calendar_feeds` создаётся при запуске.

Проверка HTTP и PostgreSQL с откатом временной схемы:

```bash
venv/bin/python tests/check_calendar_sync.py
```

[Apple: импорт из Mail](https://support.apple.com/guide/iphone/ipha0d932e96/ios),

## Рекомендации v2

В карточке доступны бюджет (5/10/20/50/100 тысяч тенге или без ограничения) и интересы.
После отказа подборка обновляется, отклонённая идея исключается для этого события.
Причину отказа можно указать отдельно: дорого, уже есть, не подходит по интересам, другое.
Отказ по интересам влияет на похожие идеи для того же события; отказ «уже есть» не снижает рейтинг всей категории.

Каталог дополнен 18 нейтральными идеями. Указанные минимальные суммы — редакционные ориентиры для поиска,
не цены конкретных товаров и не подтверждение наличия. При ограниченном бюджете идеи без оценки цены исключаются.
Пол не ограничивает доступные увлечения. Ранее выбранные теги сохранены и доступны для изменения.

`gift_impressions` хранит показы, позицию, оценку, бюджет, интересы и версию алгоритма.
`gift_ml_dataset` хранит выборы, отказы и их причины; отсутствие клика не превращается в отказ.
Это подготовка данных для обучения ранжирования; обученная ML-модель пока не используется.

Проверка рекомендаций на PostgreSQL в откатываемой временной схеме:

```bash
python tests/check_recommendations.py
```

### Товары с фотографиями (23.10.2026)

В рекомендациях показываются только проверенные карточки товаров с прямой ссылкой и фото.
Стартовая подборка: 18 товаров Kaspi в `catalog/products.json`. Ссылки, изображения и цены
взяты с публичных карточек/результатов поиска Kaspi для Алматы 23.10.2026.
Это ручная подборка, не автоматическая интеграция API; наличие, цены и доставка могут измениться.
Возрастные границы — редакционный фильтр рекомендаций, а не сертификация товаров.
Старые общие идеи и история оценок остаются в БД, но общие идеи не участвуют в выдаче.

Фото, подпись и кнопки отправляются одной карточкой. Telegram file_id кешируется после
успешной отправки; выбранное фото сохраняется в событии и используется в напоминаниях.
Если изображение недоступно, остаётся текст со ссылкой; сбой фото не отменяет напоминание.
`/clean` удаляет и фотокарточки интерфейса, сохраняя напоминания.

Для пополнения каталога подготовьте JSON по примеру `catalog/products.json`:

```bash
venv/bin/python scripts/import_gifts.py catalog/products.json
venv/bin/python scripts/import_gifts.py catalog/products.json --apply
```

Первая команда только проверяет данные. Вторая добавляет/обновляет товары по прямой ссылке
в БД из `DATABASE_URL`; обновление фото сбрасывает кеш Telegram. Перед импортом запустите
текущую версию бота для применения миграций. Импорт поддерживает URL Kaspi, Wildberries и Ozon,
но в стартовой подборке пока только Kaspi. Фото обязательно, `price_checked_on` — дата проверки
цены в формате YYYY-MM-DD. Не подставляйте поисковую выдачу вместо карточки товара.
Новые позиции из встроенного JSON добавляются при старте без перезаписи существующих данных.
Платные места, партнёрские выплаты и отслеживание покупок пока не включены.
